# Aviation LLM Dataset Standard

## 목적

이 문서는 항공 특화 LLM 프로젝트에 필요한 데이터셋 구조와 품질 기준을 정의합니다. 데이터는 항공 안전, 운영 절차, 항공사 정책, 정비/금융 문맥을 포함할 수 있으며, 실제 운영용으로 배포 전에 보안, 정책, 규정 준수 검증을 거쳐야 합니다.

## 1. 데이터 소스

### 권장 소스
- 항공 안전 절차서
- 비상 절차 매뉴얼
- 항공사 운영 지침
- 정비 절차 문서
- 기상/운항 관련 정책
- 항공 금융 및 위험 관리 문서
- 국가/국제 항공 규정(라이선스 검토 후 사용)

### 금지 사항
- 검증되지 않은 커뮤니티 글
- 사실 확인이 어려운 사용자 게시글
- 내부 비공개 문서 무단 사용
- 항공 운영 결정에 직접 사용될 수 있는 불검증 데이터

## 2. 데이터 형식

### 2.1 Instruction-tuning JSONL

```json
{
  "instruction": "비상 상황에서 조종사는 무엇을 우선 점검��야 하나요?",
  "input": "엔진 이상 경고와 높은 고도",
  "output": "항공기 상태를 확인하고, ATC와 통신하며, 체크리스트와 항공사 SOP를 따라 안전한 착륙 가능 경로를 평가합니다."
}
```

### 2.2 RAG 문서 데이터

```json
{
  "id": "doc-001",
  "source": "flight_operations_manual",
  "title": "비상 절차",
  "text": "비상 상황에서는 항공기 상태, 통신, 기상, 항공 교통 관제 상황을 우선 점검하고 관련 절차를 준수해야 합니다.",
  "language": "ko",
  "category": "operations",
  "confidence": 0.96
}
```

## 3. 문서 전처리

- 텍스트 정규화
- 중복 제거
- 도메인 용어 표준화
- 불필요한 잡음 제거
- 문장 길이 제한 및 청킹
- 문서 단위/절차 단위 분리

## 4. 안전 검증 기준

- 비행 절차는 반드시 문서 근거 기반으로 정리
- 추정 및 불확실한 내용은 포함하지 않음
- 비상 절차는 단정적 표현을 피하고, 해당 문서 참조형 표현 사용
- 금융/운항 데이터는 별도 카테고리로 구분

## 5. 품질 체크리스트

- 데이터의 출처와 라이선스 확인
- 규정 준수 여부 검토
- 설명 가능한 문맥 여부 확인
- 문서가 최신인지 확인
- 실제 운영 절차와 일치하는지 검토
